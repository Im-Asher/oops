# 画布工作台 UI 设计稿（canvas-editing）

> 产出方式：ui-ux-pro-max 技能（`--design-system` + `style` / `typography` / `ux` 域检索）。
> 适用范围：canvas-editing 变更的 2.x（布局与上屏）、3.x（编辑与导出）实现依据。
> 状态：待用户评审确认；确认后按稿实现。

## 0. 对技能默认输出的取舍（重要）

ui-ux-pro-max 的 `--design-system` 默认产出是**落地页导向**的，直接套用会跑偏，故做如下调整：

| 技能默认建议 | 本稿取舍 | 理由 |
| --- | --- | --- |
| Pattern: Hero + Features + CTA | **不采用** | 落地页结构，与应用型工作台无关 |
| Typography: Fredoka + Nunito（playful/children's apps） | **不采用** | 电商设计工具需专业感；沿用项目既有 Geist（`layout.tsx` 已注入） |
| Style: Micro-interactions（gesture / tactile feedback） | **采用** | 与画布的滚轮缩放、拖拽平移、框选高度契合 |
| Colors: Canvas Neutral + High Contrast（#111111 / #FAFAFA / #000） | **采用并转为深色工作态** | 中性高对比适合图像工具；深色底让商品图更突出 |
| Anti-patterns: 复杂 onboarding、性能差 | **采用** | 空态引导保持一句话；预览降采样保 60fps |

补充检索结论：
- `style` 域首选 **Dark Mode (OLED)**（#000000 / #121212，WCAG AAA，Tailwind 兼容 10/10）与 **Minimalism & Swiss Style**（功能优先、留白、清晰层级）——二者合并为本稿的「深色中性 + 极简功能」取向。
- `ux` 域硬性要求：图片 alt、错误用 `role="alert"`、正文对比度 ≥ 4.5:1。
- shadcn 栈提示：浮层内容优先用既有浮层组件，而非裸 `absolute` div。

## 1. 整体布局

```
┌──────────────────────────────────────────────────────────────┐
│  画布区（占满视口 100vw×100vh，深色底 #0A0A0A）                │
│                                                              │
│  ┌────────────────┐                        ┌─────────────┐  │
│  │ 悬浮聊天面板    │                        │ 编辑工具条   │  │
│  │ (左, 380px)    │       [激活图]          │ (右上, 浮)   │  │
│  │ 可折叠 ⇄       │                        │ 裁剪 滤镜    │  │
│  │                │                        │ 导出 重置    │  │
│  │ ─ 消息列表 ─   │                        └─────────────┘  │
│  │ [缩略图][缩略图]│                                          │
│  │ ─ 输入框 ─     │                                          │
│  └────────────────┘                                          │
│                          ┌──────────────────────┐           │
│                          │ 查看工具条 (底部居中)  │           │
│                          │ −  100%  +  适应  1:1 │           │
│                          └──────────────────────┘           │
└──────────────────────────────────────────────────────────────┘
```

- **画布为主体**：`fixed inset-0`，占满视口，无页面级滚动条。
- **聊天面板悬浮其上**：左侧浮动，距边 `top-4 left-4 bottom-4`（浮层不留死贴边），宽 380px，圆角 + 细边框 + `backdrop-blur`。折叠后仅留一个左侧悬浮圆形按钮（聊天气泡图标）唤回。
- **折叠时画布完整无遮挡**（对应 canvas-workspace spec「折叠聊天专注看图」）。
- 面板与画布的 z-index：面板 30，工具条 20，裁剪蒙层 10（遵循 z-index 10/20/30/50 刻度）。

## 2. 设计令牌（Tailwind v4 / 与 shadcn 现有组件一致）

| 角色 | 取值 | 说明 |
| --- | --- | --- |
| 画布底 | `#0A0A0A` | 深色中性，商品图更突出 |
| 面板底 | `#18181B` (zinc-900) / 半透明 + blur | 与 light 模式相反的深色玻璃 |
| 面板边框 | `#27272A` (zinc-800) | 两种模式下均可见 |
| 主文本 | `#FAFAFA` | 对 #0A0A0A 对比度 ~19:1 |
| 次要文本 | `#A1A1AA` (zinc-400) | 对深色底 ~7:1，安全 |
| 主操作（导出/发送） | 白底 `#FFFFFF` + 深字 | 深色 UI 中最高对比 CTA |
| 次操作 | `#27272A` 底 + `#FAFAFA` 字 | hover 提亮一档 |
| 强调/激活态 | `#FFFFFF` 描边 2px + 微弱外发光 | 缩略图高亮、裁剪框 |
| 危险（取消/重置） | 无红色强依赖，用文字 + 边框表达 | 避免仅靠颜色传达 |

- 过渡统一 `duration-200`（微交互 150–300ms 区间内）。
- 尊重 `prefers-reduced-motion`：缩放/位移动画降级为瞬时。

## 3. 五个设计对象

### 3.1 画布（激活图 / 空态）

**空态引导**（会话尚无图片时，画布正中）：
- 单个线性 SVG 图标（图像/画框意象，**不用 emoji**），尺寸 48px，`#3F3F46`。
- 主文案：`画布还是空的`
- 副文案：`在左侧聊天里描述你想要的图片，生成后点击图片即可上屏`
- 不出现多于一个操作按钮（避免复杂 onboarding）。

**激活图态**：
- 图片 `object-contain` 居中，外层容器用 `transform: translate(x,y) scale(s)` 承载缩放平移（`transform` 走 GPU，不触发重排）。
- 图片本身不被修改，任何缩放平移都不重编码（对应 spec「查看不损图」）。
- 同一时刻至多一张激活图；切换时旧图直接替换，不保留副本。

### 3.2 悬浮聊天面板

- 结构自上而下：会话标题 + 新建/折叠按钮 → 消息列表（滚动）→ 输入框 + 发送。
- **复用现有消息渲染**：从 `src/app/chat/page.tsx` 抽出消息气泡、SSE 流式逻辑、agent 选择，仅换容器，行为零回归（对应 chat-streaming delta spec）。
- 折叠/展开按钮为图标按钮，带 `aria-label`，44×44 触控区。

### 3.3 消息图片缩略图（上屏入口）

- 缩略图固定 ~96px 见方，圆角，`cursor-pointer`，hover 提亮并显示「上屏」浮层按钮。
- 点击缩略图或「上屏」按钮 → 该图成为激活图（携带 `assetId` + `url`）。
- **激活态**：当前激活图对应缩略图加 2px 白色描边 + 外发光，切换时高亮随之转移。
- 每张缩略图 `alt` 用生成时的 prompt 摘要（缺失时回落「生成的图片」）。

### 3.4 工具条

**查看工具条（底部居中，浮层）**：
`−` / 缩放百分比（点击重置为适应） / `+` / `适应` / `1:1`
- 滚轮以指针为中心缩放，范围 **25%–400%**；按钮每档 ×1.2。
- 拖拽平移，光标 `grab` / `grabbing`。
- 键盘可达：`+` `-` `0`（重置）`Esc`（取消当前模式）。

**编辑工具条（右上，浮层）**：
`裁剪` `滤镜` `导出` `重置`
- `导出` 仅在 `dirty`（有裁剪或滤镜改动）时可用；否则禁用并 `title="未做修改，无需导出"`（对应 image-editing spec「无编辑不导出」）。
- 进入裁剪模式时，底部工具条替换为 `取消` / `确认裁剪` 两个操作。

**滤镜面板（右侧浮层，点「滤镜」展开）**：
- 三个滑杆：亮度、对比度、饱和度，范围 0%–200%，默认 100%，实时预览。
- 预设（点击即应用一组参数）：

| 预设 | brightness | contrast | saturate |
| --- | --- | --- | --- |
| 原图 | 100% | 100% | 100% |
| 鲜明 | 105% | 115% | 135% |
| 柔和 | 110% | 90% | 85% |
| 暖调 | 105% | 100% | 120% + sepia(15%) |
| 冷调 | 100% | 105% | 95% + hue-rotate(-8deg) |
| 黑白 | 100% | 110% | 0% |

- 预览用 CSS `filter` 串，导出用同一串赋给 `ctx.filter`——**共用一份参数，零色差**。
- 每个滑杆有可见 label 与当前数值（不靠颜色单独传达）。
- `重置` 一键回到原图参数。

### 3.5 裁剪

- 进入裁剪模式后图片上覆盖半透明蒙层，选区为高亮矩形（四周 8 个手柄或简化为四角手柄）。
- 选区外 `#000/60`，选区内保持原亮度，实时预览裁剪结果。
- `确认裁剪` → 编辑态更新为裁剪后画面；`取消` → 还原到进入前（对应 spec 两个 scenario）。
- 仅改编辑态，不碰原 asset。

## 4. 导出视觉反馈

- 点击导出：按钮进入加载态（禁用 + spinner），`role="status"` 提示「导出中…」。
- 成功后：聊天面板追加一条 assistant 图片消息（可直接上屏），画布切换/保持激活为新图；`role="status"` 提示「已导出为新图片」。
- 失败：`role="alert"` 显示可读错误（保留服务端结构化错误文案），不暴露堆栈。

## 5. 组件与状态落点（实现约束）

```
src/components/canvas/
  canvas-stage.tsx        全屏画布容器（transform 承载缩放平移）
  canvas-empty-state.tsx  空态引导
  view-toolbar.tsx        底部查看工具条
  edit-toolbar.tsx        右上编辑工具条（含导出/重置）
  crop-overlay.tsx        裁剪蒙层 + 选区 + 确认/取消
  filter-panel.tsx        滑杆 + 预设
src/components/chat/
  floating-chat-panel.tsx 悬浮面板（折叠/展开）
  message-list.tsx        复用消息渲染
  image-thumbnail.tsx     缩略图 + 上屏 + 激活高亮
src/lib/canvas/
  canvas-reducer.ts       { activeAsset, view{scale,x,y}, edit{crop,filters}, dirty }
  filter-string.ts        filters → CSS filter 串（预览/导出共用）
  export-canvas.ts        全分辨率离屏合成 → toBlob(PNG)
```

- 激活图与视图/编辑态均为 **UI 状态**，不落库（design 决策 6）；切图重置 `view` 与 `edit`。
- 缩放平移仅改 `view`；裁剪与滤镜写入 `edit` 并推导 `dirty`。

## 6. 可访问性与性能清单（交付前自检）

- [ ] 图标用 Lucide SVG，无 emoji 图标
- [ ] 所有可点元素 `cursor-pointer`；hover 有可见反馈
- [ ] 图标按钮均有 `aria-label`；触控区 ≥ 44×44
- [ ] 焦点环可见（`focus-visible`）
- [ ] 图片均有 alt（缩略图用 prompt 摘要）
- [ ] 错误/状态用 `role="alert"` / `role="status"`
- [ ] 正文对比度 ≥ 4.5:1（#FAFAFA/#A1A1AA on #0A0A0A 均满足）
- [ ] `prefers-reduced-motion` 生效
- [ ] 跳转/切换不引发布局跳动（缩放只动 transform）
- [ ] 375 / 768 / 1024 / 1440 四档无横向滚动（小屏下面板改为全宽抽屉）

## 7. 评审决议（2026-09-28 已确认）

| 议题 | 决议 |
