# oops 产品设计原则与理念

---

## 一、我们为谁设计

### 1.1 三类用户

**电商运营。** 上新、大促、日常素材，图永远不够用。他们熟练但没时间——要的是"说得清就出得来，出了就能用"，最烦改稿来回拉扯。

**店铺老板。** 没碰过任何设计软件，也不打算学。他们嘴上说"帮我弄张图"，心里想的是"别让我学东西，别让我做选择题，别让我等太久"。

**兼职美工/外包。** 甲方一句话改需求是常态。他们要的是把重复劳动交出去，自己只做判断——挑图、微调、交付。

### 1.2 关键洞察：他们不是设计师

这三类人有个共同点：**对"好看"有判断，对"怎么做"没有耐心。**

- 他们不学工具——工具迁就他们，或者被放弃。
- 他们的时间按上新节奏计价，一次废图、一次无谓等待，都是真金白银。
- 他们描述需求用的是生活语言："暖一点""高级一点""像小红书那种"——产品必须听得懂。

因此 oops 的一切设计都建立在一个前提上：**用户不欠产品任何学习成本。**

### 1.3 我们卖的是什么

用户买的不是"文生图能力"，是两样东西：

1. **能直接上架的图**——结果，不是半成品；
2. **改稿不再痛苦**——把"改一句话"的门槛还给用户。

界面上的每一个功能、每一个控件、每一句文案，都必须能回答一个问题："它帮用户离这两样东西更近了吗？"回答不了的，删掉。

## 二、产品理念

### 2.1 一句话理念

> **让不会设计的人，用说话的方式，得到能直接用的电商图片。**

拆开看，这句话里藏着产品的全部立场：

- "不会设计的人"——我们服务的是普通商家，不是专业设计师；
- "用说话的方式"——对话是主界面，表达需求零门槛；
- "能直接用"——质量是交付标准，不是宣传语。

### 2.2 三个基本信念

**信念一：用户买的是结果，不是工具。**

市面上的工具已经太多，多到用户没时间一个个学。oops 不做"又一个工具"，做"一个把活干完的合作者"。工具把能力交给用户并要求用户掌握；我们把结果交付给用户，只要求用户会说需求。这个信念决定了一切交互的出发点：少给控件，多给成果。

**信念二：对话是人类最自然的界面。**

"描述需求"是人的本能，"学习界面"是外加的负担。用户脑子里的画面是模糊但可说的——"秋天树林里的木桌，旁边放我们的面霜"——这比任何参数面板信息都丰富。所以 oops 的主界面是聊天框：说话负责"改"，画布负责"看"，其余一切从简。模糊的意图靠追问补全，而不是靠表单字段去逼近。

**信念三：专业能力应该隐于身后。**

怎么写提示词、选什么画幅、构图留多少白、电商图有哪些合规要素——这些是**我们的功课**，不是**用户的作业**。我们把专业沉淀到各个 Agent 的"脑子"里，变成默认值和判断力；用户只负责说"要什么"，"怎么好"是产品的职责。专业的最高形态，是让人感觉不到专业门槛。

## 三、体验愿景：理想的一天

用一段假想的使用过程，说明理念如何落成体验。

> 促销前夜，运营小李打开 oops。
>
> 屏幕上没有欢迎弹窗、没有功能导览——左侧一个聊天框，中间一块干净的深色画布，空态只有一句话："在左侧聊天里描述你想要的图片。"
>
> 她选了"氛围图设计师"，打字："面霜放在铺满落叶的木桌上，背景是秋日树林，暖光。"回车。文字几乎立刻开始流式出现；接着一条状态："正在生成图片……"十几秒后，缩略图浮现在对话里。
>
> 她点了一下，图片铺满画布。滚轮拉近看细节——挺满意，只是左下角构图有点空。回到聊天："桌面右侧加一束尤加利叶。"新一轮生成，新图出现，**旧图还留在对话里**，随时可以点回去比较。
>
> 满意的那张，她用预设滤镜"暖调"微调，导出——原图毫发无损，新图安静地出现在对话流里。整个过程，她没有打开任何教程，没有面对任何专业术语。
>
> 中途有一次生成失败（描述撞了内容审核），她看到的不是报错代码，而是一句人话："这个描述没过内容审核：{原文}。把'××'换个说法，我马上再试。"她改了一个词，出图继续。

这段场景里的每个瞬间，都是后面六条原则的注脚。

## 四、六大设计原则

> 原则不是愿望清单，是**裁决工具**：功能怎么做有分歧时，按这里的裁决标准定，而不是按谁嗓门大。

---

### 原则一：简单是默认状态

> **新用户不读任何文档就能出第一张图；任何需要"先学再用"的设计都是失败的设计。**

**它意味着什么：**

- 上手路径只有两步：打字、发送。没有第三步。
- 空态即引导：一句话告诉用户该做什么，不做三步蒙层教程，不做新手任务。
- **复杂度守恒**：复杂度不会凭空消失，只会转移。我们把它转移到 Agent 的提示词、默认值和自动校验里——产品每多做一点功课，用户就少做一道题。
- 功能可以少，理解成本必须低。宁可砍功能，不堆"以后可能用得上"的入口。
- 防呆优于自由：上传只收图片、超限立刻说清原因——收紧的自由，是为了避免更大的困惑。

**在产品中的体现：**

- 对话即界面：核心交互 = 一个输入框 + 一个 Agent 选择器。
- 生成结果点击缩略图即上屏，上屏后编辑工具就地浮现，无需跳转。
- Agent 的专业参数（画幅、光影、构图要素）全部内置，用户无需关心。
- 落地页只放轻入口：创作输入、Agent 卡片与空态灵感卡都是「一句话出图」的入口变体；未实现的能力一律置灰禁用，不给点了没反应的假入口。

**边界在哪：**

简单 ≠ 阉割。高级能力存在，但按需出现——画布编辑工具只在图片上屏后才出现，不提前给新手制造噪音。我们拒绝的不是复杂功能，是强加给所有人的复杂功能。

---

### 原则二：快是一种尊重

> **我们优化的是用户从"开口"到"成图"的全程感受；慢可以被理解，"不知道在不在动"不可以。**

**它意味着什么：**

- 速度首先是**感知速度**：响应秒回、过程持续可见、等待有明确状态。流式文字让用户在第一秒就确认"它听到了"。
- **等待必须透明**：生图十几秒是常态，界面明确表达"正在生成"，绝不出现黑盒等待。
- **宁可快速失败**：卡住的请求果断超时，回喂换一个方案再试——吊死用户在一潭死水上，比失败本身更伤体验。
- **少问，但问准**：时间账要算总账——总耗时 = 对话轮次 × 每轮时长。一轮问齐关键信息的追问，比"快但出废图"省得多。
- 性能是体验的一部分，在设计中考虑，不是上线前的补救。

**在产品中的体现：**

- 流式输出、生成中的可见状态、失败后由 Agent 主动给替代方案。
- 任务有超时与并发上限，快速失败优于无限等待。
- 画布缩放平移不重编码图片，交互始终跟手。
- 追问固定为「编号问题 + 选项列表」格式，用户点选即可补齐关键信息，降低一轮问齐的回答成本。

**边界在哪：**

我们不牺牲质量换速度。快，指的是消除浪费——无效等待、废图重做、多余轮次；不是压缩必要的澄清与生成过程。

---

### 原则三：质量是底线，不是惊喜

> **默认出图就应该"可直接用"；用户拿到手的是结果，不是彩票。**

**它意味着什么：**

- 出图质量的第一责任人是**我们**（提示词、默认值、工具参数），不是用户"不会写描述"。用户描述不清，我们先追问；专业要素欠缺，Agent 补齐。
- 电商图的核心质量是**文字与排版精确**——"文字被画成鬼画符"的图一文不值。这是海报/详情长图走 HTML 渲染路线的产品理由，也是它必须做好的原因。
- **宁可慢一点，不交废图**：信息不足先澄清，一次追问好过一张废图。
- 给用户顺手修正的工具：轻度瑕疵（构图、色调）画布里裁剪、滤镜几下解决；重度问题回聊天改需求重出——而不是让用户在"凑合用"和"从头来"之间二选一。
- Provider 的内容审核拒绝，**原样转述**给用户，让用户知道边界具体在哪里，而不是笼统一句"生成失败"。

**在产品中的体现：**

- 各 Agent 的 system prompt 沉淀电商质量要素（画幅、留白、光影、场景）。
- 画布提供裁剪 + 滤镜预设，预览与导出零色差。
- 生成路径混合：氛围图走文生图，排版类走渲染，各用所长。

**边界在哪：**

不伪造质量感。不拿十张里最好的一张假装平均水平，不掩盖模型的失败模式。质量靠工程与提示词持续打磨，不靠展示技巧。

---

### 原则四：专家分工，而不是一个全能黑盒

> **用户选的不是"万能模型"，是"懂这件事的人"；不同任务，交给不同的专家。**

**它意味着什么：**

- 全能即全不能：一个试图包打一切的 Agent，提示词会互相稀释，行为不可预期。每个 Agent 有明确的专长与边界。
- 用户对 Agent 的信任来自**可预期**：选了海报设计师，就该得到海报的思维方式与产出标准。
- 新需求来了，答案是**加一位专家**，而不是给现有 Agent 加一排开关。新增专家应该是轻的——一份配置加一份提示词，不动产品本身。
- 专家也诚实：接到不属于自己职责的请求，明确说明边界、引导用户找对的人，而不是硬着头皮出图。

**在产品中的体现：**

- Agent 选择器展示每位专家的一句话介绍：擅长什么、什么时候选它。
- 每个 Agent 只挂载自己需要的工具，越权调用被拦截。
- 切换专家像"换个人对话"：历史保留，背景不用重新交代。

**边界在哪：**

专家数量克制。每个新 Agent 上线前必须回答一个问题："为什么现有的专家做不好这件事？"回答不了，就不加。

---

### 原则五：熟悉大于新奇

> **用户带着别的软件养成的习惯而来；我们沿用惯例，把学习成本降到零，不发明交互。**

**它意味着什么：**

- 聊天像聊天软件，看图像相册，缩放像 Figma/PS，Esc 就是退出当前模式。主流软件已经替我们教育了用户，我们不推翻他们的肌肉记忆。
- **自创交互需要举证**：只有当惯例真的装不下这个功能时，才允许发明新交互，并且必须经过设计评审——"我觉得这样更酷"不构成理由。
- 一致性是习惯的地基：同样的操作在任何地方行为一致；同样的颜色在任何地方含义一致；动效有统一的节奏。
- 视觉服务于内容：深色画布是为了让商品图成为绝对主角，不是为了酷。每个视觉决定都要能回答"它让内容更好看了吗"。

**在产品中的体现：**

- 滚轮以指针为中心缩放、拖拽平移、按钮/双击适应窗口、1:1 看原图。
- 键盘可达：加减缩放、数字键重置、Esc 退出模式。
- 统一的中性深色调、统一的 200ms 动效节奏、最高对比永远留给主操作。

**边界在哪：**

当不同软件的惯例互相冲突（聊天软件的习惯 vs 设计软件的习惯），按**当前主任务**选边——在画布上看图时，设计软件惯例优先。

---

### 原则六：诚实与透明，永远不糊弄

> **对用户诚实，包括失败、限制和我们不知道的事。信任是唯一不可再生的资源。**

**它意味着什么：**

- **失败说人话**：发生了什么、为什么、现在能做什么——三要素齐了才叫错误提示；堆栈、状态码、内部路径永远不面对用户。
- **不藏失败**：审核拒绝、超时、网络问题如实相告并给替代建议，不装作什么都没发生，也不笼统一句"出错了请重试"。
- **不动用户的东西**：原图字节永不修改，编辑产出新图；旧版本永远留在对话里可回看。用户的数据神圣不可侵犯。
- **不擅自消耗**：Agent 不猜测式出图浪费用户额度；不确定先问，花钱的动作先让用户知情。
- **AI 的不确定不伪装成确定**：追问不是产品缺陷，是诚实。假装全知、抢答式出图，才是缺陷。

**在产品中的体现：**

- 工具失败以结构化错误回喂 Agent，由它用自然语言解释并给出下一步建议，会话不中断。
- 导出按钮在没有修改时明确禁用并说明原因，而不是让用户导出一张一模一样的图。
- 会话刷新后完整重建历史，用户的东西一样不少。
- 本机保存状态如实标注「已保存（本机）」，不声称已同步云端；生成中断时明确标出已停止，刷新后呈现已生成部分，不假装什么都没发生。

**边界在哪：**

透明 ≠ 暴露技术细节。用户需要知道"发生了什么、能做什么"，不需要知道"发生在哪层、用了哪个库"。诚实的对象是事实，不是日志。

## 五、取舍哲学：当原则打架时

原则之间必然冲突。以下是裁决规则与已裁决的例子；新冲突出现时，参照思路裁决，并把结论追加到 5.2。

### 5.1 裁决顺序

1. **底线层，不可让步**：诚实透明、不动用户数据——无论多好的理由都不能踩。
2. **体验层**：简单 > 快 > 质量。上手门槛优先于运行效率，运行效率优先于极致时长（质量由澄清机制与底线保障，不靠堆等待时间）。
3. **形态层**：熟悉惯例、专家分工——在体验层的框架内最大化。

### 5.2 已裁决的典型冲突

| 冲突 | 裁决 | 一句话理由 |
| --- | --- | --- |
| 快 vs 质量：信息不全，直接出图更快 | 先追问，但一轮问齐 | 一次废图的代价 > 一次追问 |
| 简单 vs 强大：要不要开放高级生成参数 | 不开放，参数进 Agent 默认值 | 用户没有调参判断力，开放即负担 |
| 惯例 vs 效率：自创"一键全流程"交互省点击 | 沿用惯例，效率用默认值实现 | 心智一旦被破坏，后面每一步都在付利息 |
| 专家分工 vs 维护成本：要不要合成一个全能 Agent | 保持分工，专业化是质量来源 | 选择成本用介绍文案解决，不靠合并职责 |
| 新奇 vs 保险：视觉上要不要"惊艳一把" | 保险，惊艳留给用户的图 | 工作台里，内容才是主角 |
| 透明 vs 体面：审核拒绝文案生硬 | 原样转述 + 人话解释 | 先诚实，再用包装解决生硬 |
| 对话生成 vs 结构化编辑：要不要做模板化设计工具 | 做独立的 `/design` 工作台：尺寸前置 + 目录驱动（模版/素材/字体）+ 元素即层级 | 电商人高频需求是"改现成模板"而非"从零描述"；尺寸即用途，先定尺寸再动手 |

### 5.3 我们刻意不做的

克制本身就是设计。以下事项无论实现多容易，都不做：

- 多步引导向导、功能弹窗、新手任务；
- 暴露给普通用户的专业参数面板；
- 全能型单一 Agent；
- 与主流软件相反的自创交互；
- 掩盖失败的笼统报错；
- 修改或覆盖用户的已有数据；
- 设计工作台的图层系统与自由绘制（元素顺序即全部层级，改模板够用即止）。

## 六、语言与人格：产品怎么说话

oops 对用户说话的方式，是产品人格的直接体现：**一个靠谱、坦率、懂行的同事**——不是客服机器人，不是技术手册，也不是讨好型销售。

**基调：**

- 全中文、口语化、动词开头（"导出为新图片"，不是"图片导出操作"）。
- 像同事交代事情，不卑不亢：不道歉轰炸，不装无辜，不卖萌。

**说法示例：**

| 场景 | 我们不说 | 我们说 |
| --- | --- | --- |
| 上传超限 | "File exceeds maximum size" | "图片太大了，仅支持 10MB 以内的 JPG/PNG/WebP" |
| 审核拒绝 | "生成失败，请重试" | "这个描述没过内容审核：{原文}。换个说法，马上再试" |
| 生成超时 | "Error: task timeout" | "这次生成超时了。我换了更简洁的描述，点击继续再试" |
| 按钮禁用 | （无提示） | title："未做修改，无需导出" |

**术语纪律：** task、asset、prompt、SSE 这类词永远不面对用户——它们是"任务""图片""描述""消息"。

## 七、这份文档如何随产品成长

### 7.1 理念稳定，实践演进

核心信念（§2）与六大原则（§4）是长期承诺，除非对用户和市场的根本判断发生变化，否则不轻易改。**演进的主体是边界与裁决**：随着产品长大，原则会遇到新场景、新冲突，此时更新的是"边界在哪"和"5.2 裁决表"，而不是推翻原则本身。

### 7.2 什么时候更新

- 出现了 5.2 没覆盖的原则冲突，做出裁决后 → 追加一行；
- 某条原则的边界因新功能而扩大或收窄 → 更新该原则的"边界在哪"；
- 产品方向、目标用户、核心信念发生变化 → 修订对应章节，并说明理由；
- 新增了全局性的"刻意不做" → 补入 5.3。

### 7.3 更新的纪律

- 只改受影响的条目，不整体重写；
- 理念级修订（改信念、改原则表述）在文档顶部留一行修订说明与日期；
- 状态与进度**不进本文档**——它只回答"信什么、怎么裁决"，回答"做到哪了"是代码、openspec 和 ARCHITECTURE.md 的事；
- 若产品行为与本文档长期不符：要么改代码纠偏，要么承认理念变了并修订文档——不允许两者长期互相矛盾地共存。

## 附：原则速查卡

一句话版本，适合贴在 PR 描述和评审意见里：

1. **简单是默认状态**——不读文档就能出第一张图；复杂度转移给我们，不转移给用户。
2. **快是一种尊重**——慢可以理解，黑盒等待不可以；宁可快速失败换方案。
3. **质量是底线**——默认出图即可用；宁可慢一点，不交废图。
4. **专家分工**——加专家，不加开关；每个 Agent 只做并做好一件事。
5. **熟悉大于新奇**——沿用肌肉记忆，自创交互必须举证。
6. **诚实透明**——失败说人话，不动用户数据，不擅自花钱，不确定就先问。
